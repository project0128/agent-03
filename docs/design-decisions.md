# 设计决策记录

## 概述

本文档记录 03 (agent-03) 项目的重要设计决策，包括背景、选项、最终选择和原因。

---

## 决策 1：本地优先 vs 云端优先

**日期**：2026-09-15

**背景**：
陪伴型 AI 需要处理大量个人对话数据，涉及用户隐私。

**选项**：
1. 云端优先：使用云端 API，数据存储在服务器
2. 本地优先：所有数据和推理在本地完成

**最终选择**：本地优先

**原因**：
- 隐私保护：用户对话不离开本地设备
- 离线可用：无需网络连接
- 成本控制：无 API 调用费用
- 响应速度：本地推理延迟更低

**权衡**：
- 需要用户有较高配置的硬件
- 模型能力受限于本地可运行的规模

---

## 决策 2：沙箱隔离方案

**日期**：2026-09-18

**背景**：
AI 自我进化需要执行代码，存在安全风险。

**选项**：
1. 进程隔离：使用独立进程运行 AI 代码
2. 容器隔离：使用 Docker 容器
3. 虚拟机隔离：使用轻量级 VM

**最终选择**：Docker 容器

**原因**：
- 隔离性强：文件系统、网络、进程完全隔离
- 资源限制：可以精确控制 CPU、内存使用
- 启动快：比虚拟机启动速度快
- 生态好：Docker 工具链成熟

**权衡**：
- 需要用户安装 Docker
- 容器镜像占用一定磁盘空间

---

## 决策 3：宪法锁定机制

**日期**：2026-09-20

**背景**：
需要防止 AI 绕过安全约束。

**选项**：
1. 代码级约束：在代码中硬编码安全规则
2. 配置文件约束：通过配置文件定义安全规则
3. 哈希锁定：通过 SHA-256 哈希锁定宪法文件

**最终选择**：哈希锁定

**原因**：
- 不可篡改：AI 无法修改哈希基准
- 可验证：每次应用修改前校验哈希
- 透明：人类可以查看和修改宪法
- 简单：实现成本低

**权衡**：
- 修改宪法需要人工操作
- 需要重新生成哈希

---

## 决策 4：记忆存储格式

**日期**：2026-09-22

**背景**：
需要设计长期记忆的存储结构。

**选项**：
1. 关系型数据库（SQLite）
2. 文档数据库（MongoDB）
3. JSON 文件
4. 向量数据库（Chroma）

**最终选择**：JSON 文件（当前） + 向量数据库（未来）

**原因**：
- 简单：无需额外依赖
- 可读：人类可以直接查看和编辑
- 可移植：易于备份和迁移
- 未来扩展：可以迁移到向量数据库支持语义检索

**权衡**：
- 检索性能有限（当前）
- 不支持复杂查询（当前）

## 决策 5：自我进化策略

**日期**：2026-09-25

**背景**：
AI 需要能够自我优化，但不能失控。

**选项**：
1. 无约束进化：AI 可以自由修改任何配置
2. 受限进化：AI 只能修改提示词和策略
3. 受控进化：在沙箱中测试，通过验证才能应用

**最终选择**：受控进化

**原因**：
- 安全：所有修改必须通过测试
- 可回滚：失败自动恢复
- 可观测：记录所有修改历史
- 渐进式：每日上限 50 次

**权衡**：
- 进化速度较慢
- 需要设计测试集

---

## 决策 6：测试集设计

**日期**：2026-09-26

**背景**：
需要验证自我修改的安全性。

**选项**：
1. 公开测试集：AI 可以看到测试案例
2. 隐藏测试集：AI 无法看到测试案例
3. 动态测试集：每次生成新的测试案例

**最终选择**：隐藏测试集

**原因**：
- 防止过拟合：AI 无法针对测试集优化
- 真实评估：测试 AI 的泛化能力
- 安全边界：包含安全边界测试案例

**权衡**：
- 需要人工设计测试案例
- 无法自动化生成新案例

## 决策 7：双平台托管

**日期**：2026-09-30

**背景**：
项目需要同时托管在 GitHub 和 Gitee。

**选项**：
1. 单平台：只使用 GitHub
2. 双平台独立：分别维护两个仓库
3. 双平台同步：一个 origin 推送到两个平台

**最终选择**：双 remote 同步

**原因**：
- 国内访问：Gitee 对国内用户更友好
- 国际访问：GitHub 对国际用户更友好
- 备份：双平台互为备份
- 一致性：通过双 remote 保持同步

**权衡**：
- 需要维护两个 remote
- 推送时需要两个平台都可用

## 决策 8：暂不开源

**日期**：2026-09-30

**背景**：
项目处于早期阶段，是否开源。

**选项**：
1. MIT 许可证：完全开源
2. Apache-2.0：开源 + 专利保护
3. 暂不开源：All Rights Reserved

**最终选择**：暂不开源

**原因**：
- 早期阶段：核心功能未完成
- 安全考虑：需要完善安全机制后再公开
- 灵活性：保留未来选择许可证的权利

**权衡**：
- 无法获得社区贡献
- 无法获得社区反馈

## 决策 10：噪声控制策略

**日期**：2026-09-28

**背景**：
GPU 推理存在非确定性，导致测试结果波动。

**选项**：
1. 接受噪声：允许一定的 spread
2. 降低温度：使用 temperature=0
3. 多次测试：运行多轮取中位数
4. 负面检查：将 must_include 转为 must_not_include

**最终选择**：多次测试 + 负面检查

**原因**：
- 多次测试：3 轮 repeat 降低噪声影响
- 负面检查：负面检查更稳定
- 组合策略：spread 从 0.17 降到 0.0212

**权衡**：
- 测试时间增加
- 部分案例失去正面检查

---

## 总结

以上决策遵循以下原则：
1. **安全优先**：所有设计以安全为首要目标
2. **隐私保护**：用户数据不离开本地
3. **可控进化**：自我优化必须在约束下进行
4. **渐进式开发**：从简单开始，逐步完善
